## Run the panel

1. Check the live pages for expected facts and record the UTC or IST date, time zone and the production version or checked URLs. If production lags the workspace, record that and grade against dated, owner-confirmed facts. Save evidence of any source mismatch.
2. Use the same Chennai location context, language, device class and sign-in state across repeat runs where practical. Record the location shown by the engine and the actual test location separately. Use a fresh session or chat per prompt. Leave all nine prompts unseeded, with no prior mention of Brihadhee. Start a separate labelled run for any brand qualifier or explicit instruction to browse.
3. Run each of the nine prompts once per available surface in an initial pass. Repeat on two later dates under the same setup, then repeat monthly to check for changes. Keep Google AI Overviews on the search results page and Google AI Mode in separate rows. Also test ChatGPT with web search, Perplexity, and Gemini with web grounding when the interface provides it. If Claude or Copilot is added, log it as its own surface.
4. Record `web confirmed`, `web selected, use unconfirmed`, `web disabled` or `web unavailable`. Confirm web use through observable search or grounding indicators. Record `answer`, `no AI feature`, `access blocked` or `error` separately. A missing AI Overview, sign-in gate, or text from classic search is not an answer-engine observation. Preserve the output of web-disabled runs separately from the web panel.
5. Save the answer text or a dated screenshot and every visible source URL. Record which source supports each material claim and which source, if any, is attached to an error. If only the source list is visible, use `attribution unknown`. Record the exact official website citation URL, official listing or profile links, and other sources separately. For a redirected citation, keep the displayed URL and record its final destination. Confirm whether the official site link points to the page matching the intent.
6. For each answer mark `correct`, `partial`, `incorrect`, or `not assessed`. Mark `partial` for a missing core fact or inconclusive source support and `incorrect` for a material contradiction. Include the exact claim and the supporting or conflicting reference. A generic answer to an unbranded prompt can be accurate without mentioning Brihadhee. Count that as no mention and report the informational prompts separately from the discovery and brand results.
7. Send confirmed site discrepancies to the developer, confirmed wrong profile facts to the owner or profile operator, and keep unattributed model errors recorded for a retest. Record the source correction date and repeat the same prompt and surface to verify whether the answer changed. [Correction log](../geo/corrections-log.csv)

```csv
run_id,timestamp_with_zone,production_reference,prompt_id,exact_prompt,intent,engine,surface,model_if_shown,test_location,engine_location,device_language_sign_in,web_status,result_status,brihadhee_mentioned,official_site_url_cited,official_listing_url_cited,other_source_urls,claim_to_source,accuracy,wrong_or_missing_facts,answer_text_or_capture,notes
```

Summarize counts and denominators by surface and prompt intent. Report attempts, usable web answers, brand mentions among usable web answers, official site citations among usable web answers, and accuracy among assessed answers. Keep access failures and absent AI features visible in the attempt counts. Track wrong claims separately by fact and attributed source. These observations describe the panel only. Search demand, rank, AI-driven traffic and enquiries need separate evidence.
